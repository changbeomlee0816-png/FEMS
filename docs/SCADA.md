# SCADA 도면 제작 프로그램

**「FEMS 수용가 등록 엑셀」을 올리면 단선결선도(SLD) SCADA 화면이 바로 만들어진다.**

접속: `npm start` → <http://localhost:3000/scada.html>

```
엑셀 업로드 ─► 셀 단위 검증 ─► 도면 자동 생성 ─► 편집/저장 ─► FEMS 포인트 등록
```

---

## 1. 엑셀 업로드와 검증

### 읽어들이는 시트

| 시트 | 쓰임 |
| --- | --- |
| `0)기본정보` | 수용가 정보, 요금적용전력·수전용량, 에너지원 계수 |
| `1)장비` | 계측 장비(전력량계 등) 등록 — 장비ID·제품명·IP |
| `2)채널활성화 및 설비트리` | 장비별 채널 → 측정부하 / 설비그룹 매핑 |
| `3)에너지트리` | **도면의 뼈대.** 계통 계층(레벨·연결계통ID) + 장비/채널 연결 |
| `4) 장비속성` | 제품별 연동 포인트 정의 → 계측포인트 생성 근거 |
| `5) 코드규칙` | 설비·에너지원 코드 + **기기종류·보호요소 코드표** |
| `6) 요금제목록` | 요금제 검증용 (없으면 내장 목록 사용) |
| `7) 수전계통` | **(선택)** 한전 수전 회선 — 회선명·공급변전소·수전전압·케이블·운전구분 |
| `8) 변압기` | **(선택)** TR 제원 — 1·2차 전압·용량·결선·%Z·냉각·온도감시 포인트 |
| `9) 구역` | **(선택)** SCADA 화면 구역 (변전동 / 기계전기실 / 제조1동 …) |

### 양식 다운로드

업로드 화면의 `양식 다운로드 (기입 예시)` · `빈 양식` 버튼으로 받는다.
양식은 **스키마·코드표에서 즉석 생성**되므로 검증기와 어긋날 수 없다 —
열을 추가하면 양식이 자동으로 따라온다. (`GET /api/scada/template?mode=example|blank`)

기입 예시는 154kV 2회선 수전 → 주변압기 → 22.9kV 모선 → 저압 부하 + 가스터빈·태양광
구성으로, 실제 공장 관제화면에서 흔한 형태를 그대로 담았다.

시트명은 공백·괄호 표기가 조금 달라도 번호 접두(`3)`)로 찾아낸다.

### 오류를 "정확히 그 셀"로 알려준다

검증기는 뭉뚱그린 메시지를 내지 않는다. 모든 지적은 다섯 가지를 함께 돌려준다.

```
[오류] 2)채널활성화 및 설비트리 · D8 · 설비코드정보
  입력된 값 : 공기압축
  문제      : 설비코드 '공기압축' 은(는) 설비코드 규칙에 없는 값입니다.
  조치      : '공기압축기' 을(를) 입력하려던 것인가요? (5)코드규칙 시트 참고)
```

셀 주소는 엑셀에서 `Ctrl+G` 로 그대로 이동할 수 있는 형태다.
`결과 복사` 버튼으로 전체 지적을 텍스트로 떠서 담당자에게 전달할 수 있다.

#### 검증 항목

**0)기본정보**
- 필수값 누락 (회사명·전화·주소·마스터계정ID·공장코드·요금제·담당자·휴대폰·이메일·요금적용전력·수전용량)
- 이메일/전화/휴대폰 형식, 공장코드 slug 규칙(접속 주소에 그대로 쓰임)
- 요금제가 `6)요금제목록` 에 있는 값인지 (오타면 근접값 제안)
- 요금적용전력 > 수전용량 (경고)
- **양식 예시 문구가 그대로 남아 있는 경우** (`홍길동`, `010-0000-0000`, `cloud fems factory code 값…`)
- 에너지 정보 27~32행: 종류가 있으면 기본단위·탭표시명 필수, 계수는 숫자

**1)장비**
- 장비ID 필수/정수/**중복** (중복 시 먼저 쓰인 셀 주소를 함께 알려줌)
- IP 주소 IPv4 형식 / IP 중복(경고)
- 포트 1~65535, 전송주기·모니터링 주기·전력채널수 범위
- 계산여부·사용여부 Y/N, 설치일자 날짜 파싱
- **제품명이 `4)장비속성` 에 정의되어 있는지** (`Accura 2300` ↔ `Accura2300` 처럼 공백 차이는 같은 값으로 처리)

**2)채널활성화 및 설비트리**
- 장비ID가 `1)장비` 에 존재하는지
- (장비ID, 채널) 조합 중복
- 채널번호가 장비의 전력 채널 수를 초과하는지 (경고)
- 설비코드가 `5)코드규칙` 에 있는지 (오타면 근접값 제안)
- 설비트리 5개 열(설비코드·그룹명·그룹ID·설비명·설비ID)의 **부분 입력** — 통합 채널은 전부 비우는 것이 정상
- 설비그룹명 ↔ 설비그룹ID 1:1 정합성, 그룹 내 설비ID 중복
- 측정부하명이 `한전메인` 인데 설비코드가 `수배전반` 이 아닌 경우 (경고)

**3)에너지트리**
- 에너지원 코드 유효성, 계통명 필수, 계통ID 중복
- 레벨 1은 연결계통ID가 0, 레벨 2 이상은 존재하는 상위 계통을 가리켜야 함
- **상위 계통 레벨 + 1** 규칙 위반
- **순환 참조** 검출
- (장비ID, 채널)이 `2)채널활성화` 에 존재하는지 / 두 계통에 중복 연결(경고)
- 최상위 계통(= 한전 메인)이 0개면 오류, 3개 이상이면 경고
- 계통ID 번호 건너뜀(참고)

**4)장비속성**
- 병합 셀(장비타입·제품명) 이어받기 처리
- Address·포인트명 필수, 계측유형/통계유형 열거값, 배율·Func Code 등 숫자
- 전력량계인데 `전력`/`사용량` 매핑(O 표시)이 없으면 경고 — 도면에 표시할 값이 없어진다

**교차 검증**
- 설비트리에는 있는데 에너지트리에 연결되지 않은 채널(참고) — 도면에 나타나지 않음

`오류가 있어도 도면 미리보기 생성` 을 켜면 구조만 먼저 확인할 수 있다.
이 모드에서는 중복 ID·순환 참조를 안전하게 정리해서 그린다(경고는 그대로 남는다).

## 2. 도면 자동 생성

`3)에너지트리` 의 계층이 그대로 단선결선도가 된다.

| 엑셀 | 도면 |
| --- | --- |
| 레벨 1 (연결계통ID = 0) | **한전 메인** — 수전점 → MOF → 주차단기 → 메인 모선 |
| 레벨 2 | 메인 모선에서 분기하는 계통 — 분기 차단기 + 그룹 모선 |
| 레벨 3 이하 | 개별 부하 — 차단기 + 설비 심볼 |

심볼은 `2)채널활성화` 의 **설비코드**로 정한다
(수배전반→스위치기어, 공기압축기/펌프/팬→전동기, 사출기/압출기→생산설비, 태양광→PV, 보일러/히트펌프→열설비, 로→로).
설비코드가 없으면 계통명 키워드로 추정한다.

배치는 leaf 슬롯 기반 tidy layout — 자식이 부모 아래에 균등 배치되고 부모는 자식 위 중앙에 온다.
사용자가 옮긴 좌표는 도면 문서에 저장되며, `자동 정렬` 로 언제든 원래 배치로 되돌릴 수 있다.

### 한전 메인이 두 개인 경우

두 가지 경로를 모두 지원한다.

1. **엑셀에서** — `3)에너지트리` 에 레벨 1 / 연결계통ID 0 행을 두 개 넣으면 수전점 두 개가 나란히 생성된다.
2. **도면 화면에서** — `＋ 한전메인 추가` 버튼. 기존 도면 오른쪽에 새 수전점이 생기고,
   속성 패널에서 이름·계약전력·수전용량을 입력한 뒤 `＋ 부하 추가` 로 하위 계통을 붙인다.

상단 KPI 스트립에는 한전 메인마다 카드가 하나씩 생기고, 계약전력 대비 사용률 미터가 함께 표시된다
(90% 초과 주황 / 100% 초과 빨강).

### SCADA 표기 (v2 확장열)

`3)에너지트리` 의 H~N 열을 채우면 도면이 실제 관제화면 수준으로 그려진다. 모두 선택 사항이라
비워두면 기존과 동일하게 나온다.

| 열 | 도면에 나타나는 것 |
| --- | --- |
| `전압(kV)` | 모선 전압 라벨 (`22.9kV BUS`) + 정격 태그 |
| `기기종류` | 심볼 결정 — VCB/ACB→차단기, TR→변압기(겹친 두 원), GEN→발전기 G, PV→태양광, MOTOR→전동기 M |
| `정격전류(A)` · `차단용량(kA)` | 기기 위 정격 태그 (`22.9kV 1250A 25kA`) |
| `정격용량(kW)` | 계약전력 대비 사용률 판정 기준 |
| `보호요소` | 기기 아래 보호계전 칩 (`50` `51` `51G`) — ANSI 기기번호 |
| `구역코드` | 구역별 화면 분할 |

`8)변압기` 를 채우면 변압기 옆에 제원 두 줄(`154/22.9kV 20MVA` / `YNyn0 %Z13 ONAN`)이 붙고,
`7)수전계통` 을 채우면 수전 카드에 회선별 계약전력이 반영된다.

전압은 **kV 단위**로 적는다 (380V → 0.38). V 로 잘못 넣으면 검증기가 잡아낸다.

### 편집 기능

| 조작 | 동작 |
| --- | --- |
| 설비 클릭 | 선택 + 속성 패널 |
| 설비 드래그 / 방향키 | 이동 (4px 격자, Shift = 20px) |
| 빈 곳 드래그 | 화면 이동 |
| 휠 | 확대/축소 |
| `＋ 한전메인 추가` | 수전점 추가 |
| `＋ 부하 추가` | 선택 계통 아래 부하 추가 |
| `선택 삭제` | 선택 설비 + 하위 전체 삭제 |
| `자동 정렬` | 최초 배치 규칙으로 재배치 |
| `PDF` | **A3 가로 1장 + 표제란**(도면명·회사·수전점·계약전력·작성일) |
| `SVG` / `JSON` | 도면 내보내기 (SVG는 스타일 내장 — 어디서 열어도 동일) |

PDF 는 외부 라이브러리 없이 만든다. PDF 표준 폰트에는 한글이 없어서 텍스트로 넣으면
설비명이 전부 깨지므로, 도면과 표제란을 캔버스에 그려 한 장의 이미지로 만든 뒤 얹는다
(`public/js/scada/pdf.js`).

## 3. FEMS 연동

### 계측 포인트 키 규칙

```
<공장코드>.D<장비ID>.C<채널>.<역할|P인덱스>

예) hanbit.D1.C1.POWER      제1수전 한전메인 유효전력
    hanbit.D4.C2.USAGE      공압기2호 유효전력량
```

역할(`POWER`, `USAGE`, `CURRENT`, `VOLTAGE`, `REACTIVE`, `PF`, `THD`, `UNBALANCE`, `ENERGY`, `RUNTIME`, `EFFICIENCY`)은
`4)장비속성` 의 매핑 열(`O` 표시)에서 나온다. 매핑이 없는 포인트는 프로파일 내 순번(`P3`)을 쓴다.

### 연동 절차

1. `연동 포인트` 탭에서 생성된 포인트 목록 확인
2. `FEMS에 포인트 등록` → FEMS `points` 테이블에 등록
   (사업장 = 공장코드, 기대 수신 주기 = 장비의 전송주기, 피크 임계 = 한전메인 계약전력)
3. 수집 프로그램이 기존 인터페이스로 값을 보낸다

```bash
curl -X POST http://localhost:3000/api/ingest \
  -H 'content-type: application/json' \
  -d '{"readings":[
        {"point_key":"hanbit.D1.C1.POWER","value":1820.5,"effective_power":1820.5},
        {"point_key":"hanbit.D4.C2.USAGE","value":42.1}
      ]}'
```

4. 도면의 `실시간` 체크 → 5초 주기로 값이 갱신되고, 가압 계통의 결선이 녹색으로 바뀐다

등록된 포인트는 **기존 FEMS 모니터링 엔진(수신율·정합성·피크·Zero 알람)의 대상이 그대로 된다.**
SCADA 도면을 위해 별도의 수집 경로를 만들지 않았다.

계측기 연동 전이라면 `데모 값 주입` 으로 화면 동작만 먼저 확인할 수 있다.

## 4. API

| Method & Path | 설명 |
| --- | --- |
| `GET  /api/scada/schema` | 양식 스키마 + 코드표 |
| `POST /api/scada/import/preview` | 업로드 → 검증 + 도면 미리보기 (저장 안 함) |
| `POST /api/scada/import` | 업로드 → 검증 통과 시 프로젝트 저장 |
| `GET  /api/scada/projects` | 도면 목록 |
| `GET  /api/scada/projects/:id` | 도면 상세 (model + diagram + report) |
| `PUT  /api/scada/projects/:id/diagram` | 편집한 도면 저장 |
| `DELETE /api/scada/projects/:id` | 도면 삭제 |
| `POST /api/scada/projects/:id/mains` | **한전 메인 추가** |
| `POST /api/scada/projects/:id/publish` | 계측 포인트를 FEMS `points` 에 등록 |
| `GET  /api/scada/projects/:id/live` | 도면 포인트 최근값 |
| `GET  /api/scada/projects/:id/points` | 계측 포인트 목록 |
| `POST /api/scada/projects/:id/demo-tick` | 데모 값 1회 주입 |

업로드는 `multipart/form-data`, 필드명 `file`, `.xlsx`/`.xlsm` 최대 20MB.
검증 실패 시 `POST /api/scada/import` 는 **422** 와 함께 리포트를 돌려준다.

## 5. 구조

```
server/scada/
  schema.js      양식의 시트/셀/열 정의 — 양식 개정 시 여기만 수정
  codes.js       공통코드(설비·에너지원·요금제) + 심볼 매핑 + 오타 근접값 제안
  workbook.js    엑셀 접근 (모든 값이 셀 주소를 달고 다니게 하는 계층)
  parser.js      시트 → 원시 모델 (형변환만, 판단 없음)
  validator.js   셀 단위 검증 → 리포트
  model.js       원시 모델 → 정규 모델 (엑셀에서 분리된 형태)
  diagram.js     정규 모델 → 단선결선도 문서 + 배치 + 한전메인 추가
  template.js    양식 생성 (스키마·코드표에서 만들어 검증기와 항상 일치)
  store.js       도면 저장/조회 + FEMS 포인트 등록/실시간 값
server/routes/scada.js   REST API
public/scada.html, css/scada.css, js/scada/*   화면 (pdf.js = PDF 내보내기)
test/make-sample.js      샘플 엑셀 생성기 (정상/오류)
test/validator.test.js   회귀 테스트
```

### 나중에 FEMS 본 시스템에 넣을 때

- **도면 생성기는 엑셀을 모른다.** `model.buildModel()` 이 만드는 정규 모델만 알면 된다.
  FEMS DB에서 같은 모양의 모델을 만들어 `buildDiagram()` 에 넘기면 도면이 그대로 나온다.
- **도면은 순수 JSON.** 서버는 좌표·구조만 결정하고 렌더링은 클라이언트가 한다.
  FEMS 화면에 `public/js/scada/{symbols,canvas}.js` 를 옮기면 같은 도면이 그려진다.
- **연동 지점은 `point_key` 하나.** 도면·수집기·모니터링 엔진이 이 키 하나로 만난다.
- API 베이스는 `public/js/scada/api.js` 의 `base` 한 줄만 바꾸면 된다.

## 6. 서버 없이 쓰기 (단일 HTML 빌드)

공개 주소: <https://changbeomlee0816-png.github.io/FEMS/scada.html>

```bash
npm run build:standalone  # → dist/scada-standalone.html  (파일로 배포할 사본)
npm run build:pages       # → docs/scada.html             (GitHub Pages 가 서비스하는 파일)
npm run build:artifact    # → dist/scada-artifact.html    (문서 골격을 host 가 씌우는 환경용)
```

기본 출력은 `<!doctype>` 부터 갖춘 **완전한 HTML 문서**다. `--fragment` 를 주면 본문만 낸다.

`<meta charset="utf-8">` 이 빠지면 브라우저가 latin-1 로 읽어 스크립트 안의 한글
시트명 리터럴(`'0)기본정보'` 등)이 깨지고, 시트 매칭이 전부 실패해 업로드가 통째로
동작하지 않는다. 정적 호스팅 중에는 charset 헤더를 안 붙이는 서버도 있어서
문서 안에 직접 넣는다.

브라우저만으로 전 과정이 도는 단일 HTML 파일이 나온다. 파일을 열기만 하면
엑셀 업로드·검증·도면 생성·편집이 모두 그 화면 안에서 실행되고,
만든 도면은 브라우저 localStorage 에 저장된다.

이게 가능한 이유는 **로직을 복사하지 않고 감싸기만 했기** 때문이다.

| 서버 | 단일 HTML |
| --- | --- |
| `server/scada/*.js` | 같은 파일을 CommonJS 셈으로 감싸 그대로 사용 |
| `exceljs` | `public/js/scada/xlsx-lite.js` (브라우저 XLSX 리더) |
| `public/js/scada/api.js` (REST 호출) | `public/js/scada/local-api.js` (동일 인터페이스, localStorage) |
| 화면 코드 (`app/canvas/charts/report/symbols`) | **수정 없이 동일** |

`xlsx-lite.js` 는 브라우저 내장 `DecompressionStream('deflate-raw')` 으로 ZIP 을 풀고
`DOMParser` 로 시트 XML 을 읽는다. 외부 라이브러리가 없다.
공유 문자열·inline 문자열·수식 결과·불리언·오류 셀을 처리하고,
날짜는 `styles.xml` 의 numFmt 로 판별해 serial 을 Date 로 되돌린다(1900 윤년 버그 보정 포함).

검증 규칙이나 배치 알고리즘을 `server/scada/` 에서 고치면 다시 빌드하는 것만으로
단일 HTML 에도 그대로 반영된다 — 두 벌을 관리하지 않는다.

### GitHub Pages 배포

이 리포지토리의 Pages 는 `main` 브랜치의 `/docs` 폴더를 그대로 서비스한다.
따라서 배포 단계가 따로 없고, `docs/scada.html` 이 최신이기만 하면 된다.

| 주소 | 내용 |
| --- | --- |
| `…github.io/FEMS/` | 기존 통합관제 데모 (`docs/index.html`) — 그대로 유지 |
| `…github.io/FEMS/scada.html` | SCADA 도면 제작 (`docs/scada.html`) |

`.github/workflows/pages.yml` 이 어긋남을 막는다.

- `main` 에 푸시 → 다시 빌드해서 달라졌으면 자동으로 커밋한다
- PR → 산출물이 낡았으면 실패시키고 `npm run build:pages` 를 안내한다

빌드는 결정적이어야 이 검사가 성립한다. 그래서 **`test/fixtures/*.xlsx` 는 커밋해서 고정**하고
(빌드에 embed 되는 샘플), 테스트는 `test/.tmp/` 에 따로 생성한다 —
exceljs 가 파일마다 생성 시각을 써 넣기 때문에, 매번 다시 만들면 산출물이 계속 달라진다.
양식이 바뀌어 샘플을 갱신할 때만 `npm run sample` 을 실행하고 결과를 커밋한다.
